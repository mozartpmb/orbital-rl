Rebuild the Dynamics

The simulator the policy trains in, taken apart and reassembled in 300 lines of Python that match the C to eight decimal places. Every block names the C function it mirrors. Tan blocks are C; blue blocks are the Python you can run.

0. What we are building

The environment is a two-body orbital simulator with impulsive burns. There is no numerical integrator anywhere. Each orbit is stored as a handful of numbers describing an ellipse, coasting only advances one angle, and burns are the one place the ellipse changes. The Python file is scripts/orbital/t3/mini_env.py:

python3 scripts/orbital/t3/mini_env.py          # three random rollouts
python3 scripts/orbital/t3/mini_env.py --check  # lockstep against the C env

The lockstep check feeds the same random actions to both and compares every observation and reward. Result: maximum difference 5.9e-8 over 418 decisions, three terminals identical in step, cause and reward.

In plain words

A satellite in orbit is on a fixed oval track. Nothing about the track changes while it coasts, only how far along the track it is. So the simulator stores the track and a clock, and coasting is "advance the clock." The one hard part is that the satellite does not move at constant speed along the track, so converting the clock to a position needs Kepler's equation. Burns change the track. Everything else is bookkeeping: fuel, finish-line checks, and packaging numbers for the policy.

Why store the clock angle and derive the real one

M advances linearly with time, so propagation is exact for any time step and warps cost nothing in accuracy. theta does not advance linearly. The C stores both but always recomputes theta from M after any change. Treat theta as a cache.

3. Three angles and Kepler's equation

There are three ways to say where a satellite is on its ellipse, and the simulator needs all three.

  • Mean anomaly M: fraction of the period elapsed since periapsis, times 2π. Uniform in time. Easy to advance, meaningless geometrically.
  • Eccentric anomaly E: the angle you get by projecting the satellite onto the circle that circumscribes the ellipse. A geometric middleman.
  • True anomaly θ: the actual angle at Earth from periapsis to the satellite. What you need for position.

Kepler's equation links M and E:

\[ M = E - e\sin E \]

It cannot be inverted algebraically, so given M the code refines a guess for E with Newton's method, five iterations, starting from E = M (or E = π for very eccentric orbits). Then E converts to θ by a half-angle identity, and the reverse map θ to M exists for use after burns.

# ── 5. Kepler's equation (orbital.h solve_kepler, eccentric_to_true, true_to_mean)
def solve_kepler(M, e):
    """M = E - e sin E, solved for E. Newton, 5 iterations, exactly as the C."""
    M = M % TWO_PI
    E = M if e < 0.8 else math.pi
    for _ in range(5):
        dE = (M - E + e * math.sin(E)) / (1.0 - e * math.cos(E))
        E += dE
        if abs(dE) < 1e-12:
            break
    return E

def eccentric_to_true(E, e):
    """E -> theta, half-angle form (no quadrant ambiguity)."""
    return 2.0 * math.atan2(math.sqrt(1 + e) * math.sin(E / 2),
                            math.sqrt(1 - e) * math.cos(E / 2))

def true_to_mean(theta, e):
    """theta -> E -> M. The sqrt factors are SWAPPED relative to the forward
    map; this is the function whose bug (2026-08-10) teleported phase on burns."""
    E = 2.0 * math.atan2(math.sqrt(1 - e) * math.sin(theta / 2),
                         math.sqrt(1 + e) * math.cos(theta / 2))
    return E - e * math.sin(E)
The bug that lived here

The two half-angle formulas differ only in which square root multiplies sine and which multiplies cosine. On 2026-08-10 it was found that the reverse map had them swapped, so it was applying the forward map twice. Since the reverse map runs only after burns, every burn corrupted M by about 2e·sin θ and teleported the satellite along its orbit. Every result before that date describes a different physics.

In plain words

The clock says "one third of the lap is done." Where is the satellite? Not one third of the way around, because it moves faster near Earth. Kepler's equation is the lookup from clock to place, and Newton's method is guess-and-correct until the equation balances.

4. Coasting is one line

static inline void propagate_orbit(Orbit* o, double dt) {
    double n = sqrt(MU / (o->a * o->a * o->a));  /* mean motion (rad/s) */
    o->M += n * dt;
    o->M = fmod(o->M, 2.0 * M_PI);
    if (o->M < 0.0) o->M += 2.0 * M_PI;
    double E = solve_kepler(o->M, o->e);
    o->theta = eccentric_to_true(E, o->e);
}
Python
# ── 6. Coasting (orbital.h propagate_orbit) ──────────────────────────────────
def propagate(o, dt):
    """Advance the clock angle by n*dt, then re-derive theta. Nothing else moves."""
    n = math.sqrt(MU / o['a'] ** 3)
    o['M'] = (o['M'] + n * dt) % TWO_PI
    o['theta'] = eccentric_to_true(solve_kepler(o['M'], o['e']), o['e'])

Mean motion \(n = \sqrt{\mu/a^3}\) is the clock rate in radians per second, fixed by the size of the orbit. Add n·dt to M, wrap to [0, 2π), and re-derive θ. Nothing else in the orbit is touched. Because this is exact, the C comment at the propagation call site notes that a warp of τ sub-steps is identical to one call with τ·dt, which is what makes the warp actions free of integration error.

5. Elements to position and back

# ── 7. Elements <-> Cartesian (orbital.h orbit_to_cartesian / cartesian_to_elements)
def to_cartesian(o):
    """Perifocal frame (periapsis on +x), then rotate by omega."""
    p = o['a'] * (1 - o['e'] ** 2)              # semi-latus rectum
    r = p / (1 + o['e'] * math.cos(o['theta']))
    h = math.sqrt(MU * p)                       # angular momentum
    xp, yp   = r * math.cos(o['theta']), r * math.sin(o['theta'])
    vxp, vyp = -(MU / h) * math.sin(o['theta']), (MU / h) * (o['e'] + math.cos(o['theta']))
    co, so = math.cos(o['omega']), math.sin(o['omega'])
    return (co*xp - so*yp, so*xp + co*yp, co*vxp - so*vyp, so*vxp + co*vyp)

def from_cartesian(x, y, vx, vy):
    """Position+velocity -> elements. Mirrors the C equatorial branch exactly."""
    r  = math.hypot(x, y)
    v2 = vx*vx + vy*vy
    vr = (x*vx + y*vy) / r                       # radial speed
    a  = 1.0 / (2.0/r - v2/MU)                   # vis-viva
    ex = ((v2 - MU/r)*x - vr*r*vx) / MU          # eccentricity vector
    ey = ((v2 - MU/r)*y - vr*r*vy) / MU
    e  = math.hypot(ex, ey)
    if e < 1e-10:
        omega, theta = 0.0, math.atan2(y, x)
    else:
        omega = math.atan2(ey, ex)
        c = max(-1.0, min(1.0, (ex*x + ey*y) / (e*r)))
        theta = math.acos(c)
        if vr < 0.0:
            theta = TWO_PI - theta
    M = true_to_mean(theta, e)
    if M < 0.0:
        M += TWO_PI
    return {'a': a, 'e': e, 'M': M, 'theta': theta, 'omega': omega}

Forward: in the perifocal frame (periapsis on the +x axis) the position and velocity are closed-form in θ, using the semi-latus rectum \(p = a(1-e^2)\), the radius \(r = p/(1+e\cos\theta)\) and the angular momentum \(h = \sqrt{\mu p}\):

\[ \mathbf r_p = r(\cos\theta, \sin\theta), \qquad \mathbf v_p = \frac{\mu}{h}\big(-\sin\theta,\; e + \cos\theta\big) \]

then rotate both by ω into the inertial frame. Reverse: from position and velocity, the size comes from the vis-viva energy equation, \(a = 1/(2/r - v^2/\mu)\); the shape and its direction come from the eccentricity vector

\[ \mathbf e = \frac{(v^2 - \mu/r)\,\mathbf r - (\mathbf r\cdot\mathbf v)\,\mathbf v}{\mu} \]

whose length is e and whose direction is ω; θ is the angle from that vector to the position, with the sign fixed by whether the satellite is moving outward or inward. The C keeps the equatorial branch verbatim from the 2D build because rewriting the eccentricity vector in an algebraically equal form changed results at the last bit in 5% of cases.

6. Burns and fuel

# ── 8. Burns and fuel (orbital.h apply_impulse) ──────────────────────────────
def apply_impulse(sat, dv_pro, dv_rad):
    """Returns |dv| actually applied. Mutates sat['orbit'] and sat['fuel_mass']."""
    x, y, vx, vy = to_cartesian(sat['orbit'])
    v, r = math.hypot(vx, vy), math.hypot(x, y)
    # local frame: prograde = v-hat, radial = r-hat (not orthogonal when e > 0)
    dvx = dv_pro * vx / v + dv_rad * x / r
    dvy = dv_pro * vy / v + dv_rad * y / r
    dv  = math.hypot(dvx, dvy)
    if dv < 1e-10:
        return 0.0
    # Tsiolkovsky: fuel burned = m_total * (1 - exp(-dv / VE))
    m_total = DRY_MASS + sat['fuel_mass']
    need = m_total * (1.0 - math.exp(-dv / VE))
    if need > sat['fuel_mass']:                  # tank runs dry mid-burn
        actual = -VE * math.log(1.0 - sat['fuel_mass'] / m_total)
        if actual < 1e-6:
            sat['fuel_mass'] = 0.0
            return 0.0
        dvx *= actual / dv; dvy *= actual / dv; dv = actual
        sat['fuel_mass'] = 0.0
    else:
        sat['fuel_mass'] -= need
    sat['orbit'] = from_cartesian(x, y, vx + dvx, vy + dvy)
    return dv

A burn is impulsive: an instant change in velocity. The requested Δv is given in the satellite's own frame (prograde along the velocity, radial along the position vector), assembled into inertial components, and added to the velocity. Then the orbit is recomputed from the new position and velocity. Fuel follows the rocket equation:

\[ \Delta m = m_{\text{total}}\big(1 - e^{-\Delta v / v_e}\big), \qquad v_e = I_{sp}\, g_0 \approx 2942\ \text{m/s} \]

so a 50 m/s burn costs about five times a 10 m/s burn, not five times exactly: 1.69% versus 0.34% of current mass. With a 15% fuel fraction the total budget is \(v_e \ln(1/0.85) \approx 478\) m/s. If a burn would need more fuel than remains, the burn is scaled down to what the tank can deliver and the tank is emptied.

Why round-trip through Cartesian

Adding a velocity vector is trivial in Cartesian and messy in elements. Converting to position and velocity, adding, and converting back is exact and reuses the two conversion functions, so the burn code contains no orbital mechanics of its own.

7. Reset: how an episode is drawn

# ── 9. Reset: sample an episode (orbital.h c_reset, T3 defaults) ─────────────
def reset(env, rng):
    """T3 headline config: LEO 300-800 km, e <= 0.05 both, gap +-180 deg,
    perigee validity, physical mean-longitude gap (phase_gap_mode 1)."""
    e_max, gap_max, cap = env['e_max'], env['gap_max'], env['cap']
    for _attempt in range(4096):
        a_init   = R_EARTH + 300e3 + rng.random() * 500e3
        while True:
            a_target = R_EARTH + 300e3 + rng.random() * 500e3
            if abs(a_target - a_init) >= 50e3:      # meaningful transfer
                break
        e_t = rng.random() * e_max
        w_t = rng.random() * TWO_PI if e_t > 0 else 0.0
        e_s = rng.random() * e_max
        w_s = rng.random() * TWO_PI
        M_s = rng.random() * TWO_PI
        # reject inits whose perigee is below the keep-out altitude
        if a_init*(1-e_s) >= EARTH_KEEPOUT and a_target*(1-e_t) >= EARTH_KEEPOUT:
            break
    env['sat'] = {'orbit': orbit(a_init, e_s, M_s, w_s),
                  'dry_mass': DRY_MASS,
                  'fuel_mass': DRY_MASS * FUEL_FRAC / (1 - FUEL_FRAC)}   # 150 kg
    # Phase gap in MEAN LONGITUDE (lambda = M + omega), so it is physical:
    gap = (2*rng.random() - 1) * gap_max
    M_t = M_s + gap + (w_s - w_t)                 # lambda_t - lambda_s == gap
    env['target'] = orbit(a_target, e_t, M_t, w_t)
    env['step'] = 0
    env['phi_prev'] = compute_phi(env)
    env['cause'] = 0
    return observe(env)

The C reset is a thousand lines because of curriculum knobs; this is the T3 headline path. Altitudes for chaser and target are uniform in 300 to 800 km with at least a 50 km difference. Eccentricities are uniform up to 0.05 with random orientation. The chaser's clock angle is random. Then rejection sampling: if either orbit's perigee, \(a(1-e)\), dips below 200 km altitude, redraw everything. Finally the target's clock angle is set so the mean-longitude gap \(\lambda_t - \lambda_s\), with \(\lambda = M + \omega\), equals a uniform draw in ±180°.

Why the gap is set in mean longitude

An earlier version offset M alone. With independent ω on each orbit, that made the physical angular gap effectively uniform over ±180° no matter what the knob said, which silently unstaged every phase curriculum at e greater than zero. Setting the gap in λ makes the knob mean what it says.

Fuel is initialised so the fuel fraction is exactly 0.15: \(m_{\text{fuel}} = m_{\text{dry}}\cdot 0.15/0.85 = 150\) kg on an 850 kg bus.

8. Termination, in order

# ── 10. Termination (orbital.h check_termination) ────────────────────────────
def check_termination(env):
    """Returns (terminal?, reward). Order matters: hyperbolic, collision,
    escape, cap, stranded, success."""
    sat, tgt = env['sat'], env['target']
    if sat['orbit']['a'] <= 0.0:
        env['cause'] = 6; return True, -10.0
    sx, sy, svx, svy = to_cartesian(sat['orbit'])
    r = math.hypot(sx, sy)
    if r < R_EARTH:                                # Earth is bodies[0]
        env['cause'] = 2; return True, -10.0
    if 0.5*(svx*svx + svy*svy) - MU/r >= 0.0:      # specific energy >= 0
        env['cause'] = 3; return True, -10.0
    if env['step'] >= env['cap']:
        env['cause'] = 4; return True, env['cap_reward']
    tx, ty, tvx, tvy = to_cartesian(tgt)
    d  = math.hypot(sx - tx, sy - ty)
    rv = math.hypot(svx - tvx, svy - tvy)
    at_target = d < env['box_r'] and rv < env['box_v']
    if sat['fuel_mass'] <= 0.0 and not at_target:
        env['cause'] = 5; return True, -10.0
    if at_target:
        initial_fuel = DRY_MASS * FUEL_FRAC / (1 - FUEL_FRAC)
        frac = max(0.0, min(1.0, sat['fuel_mass'] / initial_fuel))
        env['cause'] = 1; return True, 10.0 * (0.5 + 0.5 * frac)
    return False, 0.0

9. The shaping potential

# ── 11. The shaping potential (orbital.h compute_phi, shaping_mode 1) ────────
def wrap_pi(x):
    return x - TWO_PI * math.floor((x + math.pi) / TWO_PI)

def compute_phi(env):
    """Phi = -[ W_l * |dlambda|/pi + W_m * min(1, dv_match / DV_REF) ] <= 0."""
    s, t = env['sat']['orbit'], env['target']
    dlam = wrap_pi((s['M'] + s['omega']) - (t['M'] + t['omega']))
    de = math.hypot(s['e']*math.cos(s['omega']) - t['e']*math.cos(t['omega']),
                    s['e']*math.sin(s['omega']) - t['e']*math.sin(t['omega']))
    da_rel = (s['a'] - t['a']) / t['a']
    v_t = math.sqrt(MU / t['a'])
    dv_match = 0.5 * v_t * math.hypot(da_rel, de)   # linearised 2-impulse cost
    match = min(1.0, dv_match / env['dv_ref'])
    return -(env['w_lambda'] * abs(dlam) / math.pi + env['w_match'] * match)

Sparse terminal rewards are hard to learn from, so every non-terminal step also pays the change in a potential Φ. Two terms: the mean-longitude gap normalised to [0, 1], and a linearised two-impulse orbit-match cost (the same size-plus-shape Δv the scripted expert uses) capped at a reference. Φ is always ≤ 0 and equals 0 only at the goal.

With \(\gamma_{\text{shape}} = 1\) the per-step shaping reward is \(\Phi(s_{t+1}) - \Phi(s_t)\), so summed over an episode it telescopes to \(\Phi_T - \Phi_0\). That is the potential-based shaping guarantee (Ng, Harada and Russell 1999): the optimal policy is unchanged, the agent just gets dense progress credit. The earlier γ = 0.995 form leaked a small do-nothing income each step; setting it to exactly 1 removed that.

10. The observation, slot by slot

# ── 12. The observation (orbital.h fill_observations, slots 0-16) ────────────
def observe(env):
    s, t = env['sat']['orbit'], env['target']
    sx, sy, svx, svy = to_cartesian(s)
    r = math.hypot(sx, sy)
    vr = (sx*svx + sy*svy) / r
    vt = (sx*svy - sy*svx) / r
    v_circ = math.sqrt(MU / r)
    fuel_frac = env['sat']['fuel_mass'] / (DRY_MASS + env['sat']['fuel_mass'])
    dlam = (s['M'] + s['omega']) - (t['M'] + t['omega'])
    t_frac = max(0.0, (env['cap'] - env['step']) / env['cap'])
    obs = [0.0] * 17
    obs[0] = (s['a'] - R_EARTH) / OBS_ALT_SCALE        # chaser altitude, ~[0,1]
    obs[1] = s['e']
    obs[2], obs[3] = math.sin(s['theta']), math.cos(s['theta'])
    obs[4], obs[5] = vr / v_circ, vt / v_circ            # radial, tangential speed
    obs[6] = fuel_frac
    obs[7] = (t['a'] - R_EARTH) / OBS_ALT_SCALE        # target altitude
    obs[8] = t['e']
    obs[9], obs[10]  = math.sin(s['omega']), math.cos(s['omega'])
    obs[11], obs[12] = math.sin(t['omega']), math.cos(t['omega'])
    obs[13], obs[14] = math.sin(dlam), math.cos(dlam)   # phase gap
    obs[15] = t_frac                                    # episode clock
    obs[16] = math.cos(s['omega'] - t['omega'])         # apsidal alignment
    return obs

# ── 13. One step (orbital.h c_step) ──────────────────────────────────────────
def step(env, action):
    """Returns (obs, reward, terminal, dv_applied)."""
    reward, dv = 0.0, 0.0
    tau = ACTION_TAU[action]
    # 13a. burn (only tau == 1 non-coast actions burn; warps never do)
    if action != 0 and tau == 1 and env['sat']['fuel_mass'] > 0.0:
        dv = apply_impulse(env['sat'], *ACTION_DV[action])
    if env['sat']['orbit']['a'] <= 0.0:              # burned onto a hyperbola
        env['cause'] = 6
        return observe(env), -10.0, True, dv
    # 13b. propagate tau sub-steps, checking termination after each
    for _ in range(tau):
        propagate(env['target'], DT)
        propagate(env['sat']['orbit'], DT)
        env['step'] += 1
        term, r_term = check_termination(env)
        if term:
            return observe(env), r_term, True, dv
    # 13c. non-terminal: potential-based shaping, gamma_shape = 1 (telescoping)
    phi = compute_phi(env)
    reward += phi - env['phi_prev']
    env['phi_prev'] = phi
    return observe(env), reward, False, dv

A step has three parts. First, if the action is a burn and there is fuel, apply it. Second, propagate every body one sub-step at a time, τ times, checking termination after each sub-step so a warp can never jump over a collision or through the success box. Third, if nothing terminated, add the shaping delta. Only τ = 1 non-coast actions can burn; warps propagate only.

Why shaping runs after the termination check

At a terminal, the reward is the terminal reward and nothing else. An earlier version added the shaping delta first and then let the terminal check overwrite it, which corrupted the potential bookkeeping. The order here is the fixed order.

12. Checking it against the C

The --check mode copies the C environment's initial state into the Python one, then feeds both the same random action stream and compares all 17 observation slots and the reward at every non-terminal decision.

  ep1: terminated at decision 156: C=True py=True cause_py=stranded r_C=-10.00 r_py=-10.00

The residual is float32 rounding in the C observation buffer. Terminal observations are excluded from the comparison because the C environment auto-resets on a terminal and returns the next episode's first observation.

13. What the C has that this does not

  • 3D. Two more elements, inclination and RAAN, a 3-1-3 rotation in the conversions, and a target-plane gauge so the phase gap stays well-defined when planes differ. The 2D path is a value-gated fast path inside the same functions.
  • J2. Earth's oblateness, modelled as secular mean-element rates on top of the two-body clock:
n  = sqrt(MU/a^3)      p = a(1 - e^2)      k = 1.5 * n * J2 * (R_EQ/p)^2
RAAN_dot  = -k * cos(i)
omega_dot = +0.5 * k * (4 - 5 sin^2 i)
M_dot     =  n + 0.5 * k * sqrt(1 - e^2) * (2 - 3 sin^2 i)
a_dot = e_dot = i_dot = 0

a, e and i are constants under secular J2, so the rates are constants for the life of the element set and the map stays closed-form at any dt. The state is treated as mean elements throughout, with no conversion to osculating; the C comment quantifies that as an 83 m / 0.094 m/s per-orbit inconsistency at 5 km separation.

  • Debris. Extra Body entries on random LEO orbits, each with a 1 m hard radius and 5 km keep-out. The termination loop over bodies handles them with no special casing. Disabled for all current training.
  • The LVLH block. Slots 33 to 37: the straight-line inertial offset rotated into the target's radial/along-track frame, with a rotating-frame velocity correction. Rectilinear, per the coordinate discussion.
  • Cell mixture, fuel sampling, trajectory logging. Curriculum plumbing that draws per-episode configuration and records every sub-step for later analysis.
